# OquCat Client

Клиентское приложение платформы OquCat — маркетплейса реальных бизнес-задач для студенческих команд. Бизнес размещает проект с ожидаемым результатом и наградой, студенты объединяются в команды, предлагают решение, выполняют выбранную задачу и получают баллы и отзывы.

Этот каталог содержит веб-клиент, PWA и оболочку Tauri для desktop и Android. Сервер расположен в соседнем каталоге [`../oqucat-server`](../oqucat-server), а общее описание монорепозитория — в [`../README.md`](../README.md).

## Основной сценарий

1. Пользователь регистрируется как студент или представитель бизнеса.
2. Студент создаёт профиль и команду либо присоединяется к команде по приглашению. Команда может состоять из одного человека.
3. Бизнес формирует карточку проекта вручную, через текстовый диалог или голосового ИИ-ассистента.
4. Карточка содержит стандартные поля — контекст, потребность, пользователей, данные, ограничения, ожидаемый результат, критерии успеха, контакты и формат взаимодействия — и дополнительные динамические поля.
5. После проверки полноты карточка публикуется с наградой в баллах.
6. Капитан команды отправляет отклик с идеей, планом и ссылкой на прототип.
7. Бизнес принимает или отклоняет отклики, после чего выбранная команда выполняет проект.
8. За завершённую задачу баллы начисляются команде и каждому её участнику. Результаты отражаются в отдельных рейтингах студентов и команд.

## Реализованный функционал клиента

### Публичная часть

- адаптивная landing-страница с описанием платформы для студентов и бизнеса;
- плавная прокрутка, анимации и интерактивные 2D/3D-эффекты;
- светлая и тёмная темы;
- интерфейс на русском, английском и казахском языках;
- установка как PWA и поддержка безопасных зон мобильных устройств.

### Аутентификация и безопасность

- регистрация и вход по email и паролю;
- подтверждение электронной почты и восстановление пароля;
- OAuth-вход через Google, GitHub и Facebook;
- вход и привязка аккаунта через Telegram;
- вход без пароля через passkeys/WebAuthn;
- двухфакторная аутентификация TOTP с QR-кодом и резервными кодами;
- Cloudflare Turnstile для защиты форм входа и регистрации;
- выбор роли после регистрации и защищённые рабочие области;
- управление активными сессиями и подключёнными способами входа.

### Рабочая область студента

- каталог опубликованных проектов с серверной пагинацией;
- поиск по названию, описанию и компании;
- сортировка по полноте карточки и дате публикации;
- просмотр статуса, награды, полноты и всех стандартных и динамических полей проекта;
- создание профиля студента;
- создание и редактирование команды;
- приглашение участников, принятие и отклонение приглашений;
- просмотр состава команды и удаление участников капитаном;
- отправка отклика на проект от имени команды капитаном;
- редактирование и отзыв активной заявки;
- просмотр статуса заявки, решения бизнеса и отправленных материалов;
- отдельные рейтинги студентов и команд по баллам и отзывам;
- обработка загрузки, пустых результатов и ошибок API с возможностью повторного запроса.

### Общие возможности рабочих областей

- чат в реальном времени через Socket.IO;
- список диалогов, непрочитанные сообщения, online/offline-статусы, индикатор набора и отметки прочтения;
- профиль с изменением имени и аватара;
- настройка языка и часового пояса;
- управление passkeys, 2FA, сессиями и связанными аккаунтами;
- web push и нативные Android-уведомления;
- панель супер-администратора для адресной отправки push-уведомлений.

## Роли

| Роль         | Доступный интерфейс                                                                                 |
| ------------ | --------------------------------------------------------------------------------------------------- |
| `USER`       | Проекты, команда, отклики, рейтинги, чат и профиль                                                  |
| `BUSINESS`   | Чат и профиль; серверные API карточек, откликов и решений подготовлены для развития бизнес-кабинета |
| `SUPERADMIN` | Адресные уведомления, чат и профиль                                                                 |
| `UNASSIGNED` | Выбор роли при первом входе                                                                         |

## Архитектура

Клиент обращается к серверу по REST API с cookie-сессией. Данные каталога, команд, откликов и рейтингов кэшируются через TanStack React Query. Чат и события присутствия работают по WebSocket через Socket.IO.

Основные каталоги:

```text
src/
├── api/            # HTTP- и Socket.IO-клиенты
├── auth/           # конфигурация Better Auth
├── components/     # общие UI-компоненты и рабочая область
├── context/        # пользователь, тема и уведомления
├── locales/        # переводы en, kk и ru
├── notifications/  # web- и Tauri-уведомления
├── pages/          # landing, auth и кабинеты по ролям
├── types/          # контракты клиентских данных
└── utils/          # общие утилиты
```

## Требования

- Node.js 24 или новее;
- pnpm 12;
- запущенный `oqucat-server`;
- PostgreSQL и внешние интеграции настраиваются на стороне сервера;
- для Android-сборки — JVM 21, Android SDK и зависимости Tauri.

## Установка

```bash
pnpm install
pnpm generate-envs
```

Команда `generate-envs` создаёт файлы окружения из `.env.example`. Основные клиентские переменные:

| Переменная                      | Назначение                      |
| ------------------------------- | ------------------------------- |
| `VITE_API_URL`                  | Базовый URL REST API            |
| `VITE_WS_URL`                   | URL Socket.IO-сервера           |
| `VITE_WEB_GOOGLE_CLIENT_ID`     | Google OAuth для веб-приложения |
| `VITE_ANDROID_GOOGLE_CLIENT_ID` | Google OAuth для Android        |
| `VITE_TG_BOT`                   | Имя Telegram-бота               |
| `VITE_VAPID_KEY`                | Публичный ключ Web Push         |
| `VITE_CLOUDFLARE_SITE_KEY`      | Site key Cloudflare Turnstile   |
| `VITE_APP_NAME`                 | Название приложения             |

Не добавляйте реальные секреты и приватные ключи в Git.

## Запуск

Через окружение разработки и прокси-туннель:

```bash
pnpm dev
```

Полностью локально, с настройками из `.env.local`:

```bash
pnpm dev:local
```

Production-сборка и локальный просмотр:

```bash
pnpm build
pnpm preview
```

## Проверка качества

```bash
pnpm fmt:check
pnpm lint:check
pnpm typecheck
```

Автоматическое форматирование и исправление доступных lint-ошибок:

```bash
pnpm fix
```

## PWA и публикация

PWA-манифест, Service Worker и offline-ready инфраструктура создаются во время production-сборки. Команда `pnpm sync` передаёт собранный клиент на сервер, а `pnpm build-sync` последовательно собирает и публикует приложение.

## Tauri и Android

Инициализация Android-проекта:

```bash
pnpm tauri:android:init
```

Добавьте `src-tauri/gen/android/keystore.properties`:

```toml
password=xxxxxx
keyAlias=upload
storeFile=C:\\upload-keystore.jks
```

Затем добавьте Firebase-конфигурацию в `src-tauri/gen/android/app/google-services.json` и данные доступа к GitHub Packages в `%USERPROFILE%\.gradle\gradle.properties`:

```properties
gpr.user=github_username
gpr.key=ghp_xxxxxxxxxxx
```

Запуск и production-сборка Android:

```bash
pnpm tauri:android:dev
pnpm tauri:android:build
```

## Текущие ограничения

- бизнес-кабинет пока не предоставляет UI для создания карточек, работы с откликами и завершения проектов, хотя соответствующие серверные API уже существуют;
- отзывы и история начисления баллов реализованы на сервере, но ещё не представлены отдельными клиентскими экранами;
- публикация в Google Play и App Store и автоматическая доставка релизов пока не настроены;
- для OAuth, Telegram, push-уведомлений, Turnstile и нативной Android-сборки нужны отдельные ключи и конфигурация внешних сервисов.
